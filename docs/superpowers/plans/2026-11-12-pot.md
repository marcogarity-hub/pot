# Pot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Codex lanes follow the same steps; TDD and per-task commits still apply.

**Goal:** A working version (VP) of Pot by **Sun 2026-11-15**: on the deployed Vercel URL, members sign in by email, create a pot, pay, watch a live progress bar, lock, request payout and get paid on Arc testnet. Then polish and submit by **Fri 2026-11-20 1 PM ET**.

**Architecture:** One `Pot.sol` on Arc testnet holds every pot by `potId` and is the source of truth. Next.js route handlers sign transactions through Circle developer-controlled wallets (organizer and members) or a server relayer (pre-fund, finalize, demo top-ups). A QuickNode Stream pushes contract logs to `/api/streams`, which stores events and recomputes each pot's state from them. Supabase Realtime pushes changed rows to open browsers.

**Tech Stack:** Solidity + Arc Foundry (`arc-forge`, `arc-cast`, `arc-anvil`), OpenZeppelin `ReentrancyGuard`; Next.js App Router, TypeScript, Tailwind, shadcn/ui, viem; Circle developer-controlled wallets; Supabase Postgres + Auth + Realtime (hosted project; no Docker on this machine); QuickNode Streams; Vercel. Check versions and package names at install time (AGENTS.md rule 1).

**Spec:** `docs/superpowers/specs/2026-11-12-pot-design.md`, **including Amendments A1–A15, which override earlier sections**. Review: `docs/reviews/2026-11-12-codex-spec-plan-review.md`. Rules: `AGENTS.md`.

## Global Constraints

- Arc testnet: chain id `5042002`, RPC `https://rpc.testnet.arc.io`, Blockscout explorer.
- Native USDC is 18 decimals. Amounts are `bigint` in code and **decimal strings** in JSON/DB rows; convert input with `parseUnits(x, 18)`, never floats.
- Every server-sent transaction meets the `20 gwei` maxFeePerGas floor. With viem: `maxFeePerGas >= 20_000_000_000n`. With Circle: its own fee fields (Circle expresses fees in gwei; confirm in Task 2.1).
- No `address(0)` anywhere. Revert in the contract, 400 in the API.
- `createPot(total, share, members, deadline, threshold, objectionWindow, requestWindow)` validation: `1 <= members.length <= 20`, `share > 0`, `total == share * members.length`, `deadline > now`, `1 <= threshold <= members.length`, `60 <= objectionWindow <= 7 days`, `60 <= requestWindow <= 30 days`, no duplicates, no `address(0)`.
- States: `0 Funding, 1 Locked, 2 PayoutRequested, 3 Released, 4 Frozen`. Released and Frozen are terminal.
- Time intervals (A8): `pay`/`swapSeat` need `now < deadline`; deadline refund needs `now >= deadline`; `object` needs `now < releaseEligibleAt`; `finalizeRelease` needs `now >= releaseEligibleAt`; `expire` needs state Locked and `now >= lockedAt + requestWindow`.
- Refund eligibility: paid, not refunded, still a member, and (`Funding` with `now >= deadline`) or `Frozen`.
- Payout goes to the organizer. The organizer's own Circle wallet signs `createPot` and `swapSeat` (A1). The relayer pre-funds gas (~1 USDC), tops up demo wallets (A10) and signs `finalizeRelease`.
- Emails normalized `trim().toLowerCase()` everywhere.
- Lane ownership per `AGENTS.md`. The conductor owns `package.json`, lockfiles, shared config, `web/lib/supabase/`, `README.md` and the initial folder scaffolding.
- Each task ends: tests green, commit, append to `docs/handoffs/<lane>.md`.

## Review Focus

1. **Email casing, whitespace and duplicates.** `" Alice@X.com"` equals `"alice@x.com"`: one `users` row, one wallet, and duplicates are rejected before any Circle call. Test: Tasks 2.3, 2.4.
2. **Two requests at once** (double-tapped Pay, two tabs creating a wallet for the same email). Exactly one wallet; the second pay is a 409 with a readable message; the button disables while pending. Test: Tasks 2.3, 2.5, 4.3.
3. **Stream retries, partial failure, out-of-order delivery.** One `pot_events` row per `(tx_hash, log_index)`, and pot/member rows always equal the fold of all stored events. Test: Tasks 3.2, 3.3.
4. **Totals that don't divide evenly** (`$100` across 3). Blocked in the form and the API. Test: Tasks 4.2, 2.4.
5. **Exact-boundary timing** (paying at the deadline second, finalizing at `releaseEligibleAt`). Behaviour follows A8 at equality. Test: Tasks 1.3–1.5.
