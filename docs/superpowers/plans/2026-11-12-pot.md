# Pot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Codex lanes: follow the same steps; TDD and per-task commits still apply.

**Goal:** Ship Pot (a commitment pot for group bookings) on Arc testnet with a working Next.js frontend, a live progress bar driven by a QuickNode Stream, and a submission-ready README, by Fri 2026-11-20 1 PM ET.

**Architecture:** One `Pot.sol` on Arc testnet holds every pot by `potId` and is the source of truth. Next.js route handlers sign transactions through Circle developer-controlled wallets (members, organizer) or a server relayer (pre-fund, finalize). A QuickNode Stream pushes contract logs to `/api/streams`, which upserts into Supabase; Supabase Realtime pushes rows to open browsers.

**Tech Stack:** Solidity + Arc Foundry (`arc-forge`, `arc-cast`, `arc-anvil`), OpenZeppelin `ReentrancyGuard`; Next.js App Router, TypeScript, Tailwind, shadcn/ui, viem; Circle developer-controlled wallets; Supabase Postgres + Auth + Realtime; QuickNode Streams; Vercel. Versions: check current with the package manager/docs at install time (AGENTS.md rule 1). Do not pin from memory.

**Spec:** `docs/superpowers/specs/2026-11-12-pot-design.md` (including Amendments A1, A2). Product brief: `docs/brief.md`. Rules: `AGENTS.md`.

## Global Constraints

- Arc testnet: chain id `5042002`, RPC `https://rpc.testnet.arc.io`, Blockscout explorer.
- Native USDC is 18 decimals. All amounts are `bigint` wei-style units; convert user input with `parseUnits(x, 18)`, never `Number`/floats.
- Every server-sent transaction sets `maxFeePerGas >= 20 gwei` (`20_000_000_000n`).
- No `address(0)` anywhere: organizer, members, replacement. Revert in the contract, 400 in the API.
- `createPot` validation: `members.length > 0`, `total == share * members.length`, `deadline > block.timestamp`, `1 <= threshold <= members.length`, no duplicate members.
- Objection window: `60 <= objectionWindow <= 7 days` (UI presets: 120 s "2 minutes (demo)", 172800 s "48 hours (production)", custom).
- States: `0 Funding, 1 Locked, 2 PayoutRequested, 3 Released, 4 Frozen`. Released and Frozen are terminal.
- `has_paid` is never cleared. Objecting and refunding are independent. Refund eligibility: paid AND not yet refunded AND (`Funding` past deadline OR `Frozen`).
- Payout goes to the organizer. `createPot` and `swapSeat` are signed by the organizer's own Circle wallet (A1). The relayer only pre-funds wallets (~1 USDC each) and signs `finalizeRelease`.
- Emails are normalized `trim().toLowerCase()` at every insert and lookup.
- Lane ownership per `AGENTS.md`. Only the conductor (Marco, or the main session acting for him) edits `package.json`, lockfiles, `foundry.toml`, `tsconfig`, `next.config`, Tailwind/eslint config, `vercel.json`, `.env.example`, and `web/lib/supabase/`.
- Arc sample apps are reference only. Nothing copied.
- Each task ends: tests green, commit, append to `docs/handoffs/<lane>.md`.

## Review Focus

1. **Email casing/whitespace.** `" Alice@X.com"` and `"alice@x.com"` must hit the same `users` row and the same wallet. Test: Task 2.4.
2. **Duplicate emails, or the organizer listed as a member.** Duplicates are rejected with 400 before any Circle call. The organizer may be a member and then pays a share like anyone else. Test: Task 2.4.
3. **Total that doesn't divide evenly** (`$100` across 3). The form blocks it with "Total must divide evenly by the number of members", and the API returns 400. Test: Tasks 4.2 and 2.4.
4. **Stream retries and out-of-order delivery** (`Locked` arriving before the last `Paid`, or the same batch twice). There is exactly one `pot_events` row per `(tx_hash, log_index)`, and state never moves backwards. Test: Task 3.3.
5. **Double-tapping Pay, or paying just after the deadline.** The second request or the late payment comes back as a 409 with a readable message, not a 500, and the button disables while the request is pending. Test: Tasks 2.5 and 4.3.
